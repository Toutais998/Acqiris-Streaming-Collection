# SA230P 实测交接报告（2026-09-22）

## 已完成与核心结论

已修改唯一活动源码 CPP_IVIC_Streaming.cpp，通过指定 Visual Studio 2022 的 devenv.com 编译 Debug/Release x64，并连接真实 SA230P AQ00071865（CST，驱动3.9.20621.38，固件3.7.393.0）执行测试。信号由用户保持开启，External1实测109.84118Hz、周期9.104ms、上升530ns、下降581ns，触发仍为50Ω卡端1.5V上升沿。

**旧循环每轮sleep_for(1us)造成毫秒级休眠、主机读取积压，是此次已证实的主要软件问题。** 旧59Hz统计不能解释为硬件只接受一半触发。保留旧休眠的诊断中，marker索引和时间戳仍连续，而主机读取落后。取消休眠后完整8.1936ms记录能跟上每条line；无需为了当前问题先缩短采集窗口。

诊断也实测firstElement=8（int32元素，32字节），旧代码忽略偏移会保存错误起点。已增加驱动对齐余量并从有效偏移写出。缓冲池仍为8块。

## 32ns与触发电压

deadTime=32ns仅参与代码计算，未下发到驱动，不是本次实测。8.1936ms窗口配合9.104ms连续marker，证明当前配置可在约0.9104ms剩余时间内继续接受下一边沿；不足以测出纳秒级重武装时间。需要可调双脉冲/成组触发源、已知间隔和marker验证才能测这个极限，当前未控制信号发生器。

用户所有电压默认是1MΩ示波器读数。5/4/3V在50Ω下分别3.1/3.1/2.867V，等效源阻抗反推30.6/14.5/2.32Ω，非固定比例。限流、钳位或量程模式只是候选原因，不能定论。若低电平0V，50Ω端3.1V高电平的中点是1.55V；本次保留并实测验证1.5V。后续测2/2.5/3.5V以及低电平和波形顶部、源型号/负载模式。不要把示波器50Ω与卡50Ω同时并联导致25Ω负载。

## 尚未完成的验证与后续优先级

1. PCIe/驱动链路在取消休眠后已完成约1.8GB/s真实Streaming；当前证据不支持优先换PCIe插槽。CPU算力不足未被证实，但yield会占用一个线程较多CPU，后续若优化等待策略需重新测积压。
2. D盘为WD Green SN3000 1TB NVMe；约64GiB总RAM、检查时约43GiB可用。5秒成功写入不等于绕过Windows缓存后的长期持续落盘速度。需要受控、限大小且记录队列/写延迟/CPU的更长测试；不扩大内存池掩盖问题。
3. 并发构建时出现积压、独立复测恢复，说明系统负载可能影响采集；不能只凭这一次对照断言硬盘是唯一原因。下一轮增加每块fwrite耗时、空闲池等待、写队列峰值和Windows磁盘/单核CPU计数。
4. 检查一次10.104ms异常是否来自vDAQ line调度或marker时基，必要时示波器统计长时间周期间隔。
5. 检查ADC下限码与模拟输入量程；当前测试仅证明样本搬运/记录连续性，未验证光学信号标定。
6. 原有源文件中的未调用辅助FetchElements/SaveRecord仍保留，不将其视为活动数据路径。正常文件仍为连续int16，无marker头；不能按SaveRecord函数误读格式。
